### 🔴 A named mechanism for `NOASSERTION` — p658's caveat, now explained rather than observed

p658 recorded that `gh api search/repositories` returned `NOASSERTION` for three repositories whose payloads read `MIT`, `AGPL-3.0` and `AGPL-3.0`, and warned that `NOASSERTION` means *the classifier did not match*, never *no licence*. p659 reproduces the effect **with the mechanism attached**, on a controlled set — five repositories, one author, one licence, one pass:

| Repo | Payload bytes | Payload read at first hand | `search/repositories` `license.spdx_id` |
|---|---|---|---|
| OPTIMETA/PAIDEIA | 1,068 | MIT | `MIT` |
| OPTIMETA/PAIDEIA-codex | 1,068 | MIT | `MIT` |

| OPTIMETA/PAIDEIA-Hermes | **1,397** | MIT + appended `Attribution` | 🔴 **`NOASSERTION`** |

🔵 **Four of five agree; the fifth disagrees, and the only variable is `+329 B` of text appended after the grant.** The classifier is matching the file as a whole against a template, so *anything appended to a stock licence file flips a correct `MIT` to `NOASSERTION`* — an attribution block, a second grant, a vendor notice. The byte count is the signal that distinguishes them: a payload at the stock size with a `NOASSERTION` verdict is a classifier failure to investigate; a payload off the stock size needs the diff read before either field is trusted.

### 🆕 A sixth defect class, found at p653 — and the repository carrying it has the best licence hygiene on this shelf

`wwrwbs/AI_AWE`'s `LICENSE` is **1,865 bytes**. Canonical Apache-2.0 is 11,357. A size test calls that a truncated grant; reading it shows something different and worth naming separately:

> **Class 6 — grant by reference.** The file contains the Apache-2.0 *notice* (the short boilerplate Apache itself prescribes for source headers) — `"Licensed under the Apache License, Version 2.0 … You may obtain a copy of the License at http://www.apache.org/licenses/LICENSE-2.0"` — in place of the terms themselves.

**This is materially stronger than Class 5** (`frappe/education`'s 19-byte `License: GNU GPL V3`), and the distinction is the practical one: the notice form contains the operative grant language, names the exact version, and points at a canonical immutable URL, so *what you are permitted to do is unambiguous*. What is missing is the copy of the text that Apache-2.0 §4(a) requires a redistributor to supply. **Verdict: usable, with a one-line fix to ask for upstream** — not an unresolved permission.

🔵 **And the finding that should change how this base reads grant files.** The same 1,865 bytes then do something no other repository on this shelf does: they **enumerate every component and its licence, and state what is deliberately not redistributed** — the project's own code and LoRA adapters (Apache-2.0), a vendored `TextComplexityToolkit` (MIT) with its path given, `TAALED` inside it, the Qwen2.5-7B-Instruct base model (Apache-2.0, *"obtained separately from Hugging Face; NOT redistributed"*), and the Persuade 2.0 corpus (*"original academic-use license … the raw corpus is NOT redistributed here"*). It closes with a bias notice warning against high-stakes automated decisions without human oversight.

That is precisely the dependency-graph discipline this page spent two passes demanding — **and it is in the repository with the technically defective grant, while the 42.7k★ repository with a perfect MIT payload quietly builds an LGPL-3.0 component.** The lesson is not that size tests are useless; it is that **a short grant file is a reason to read it, not a reason to reject it**, and that licence *hygiene* and licence *form* are independent variables. Five of the six classes would pass a licence-badge check; this one fails the badge check and passes on substance.

## Agents by function

### Personalised tutoring
- **DeepTutor** — the default choice. Persistent learner model is the differentiator; a session chatbot is not a substitute.
- **Bloom** — lighter, pedagogy-led, and it ships as a Claude Code skill, which makes it the fastest thing here to demo.
- **OATutor** — structured BKT tutoring with LTI. Choose it when the client wants explainable mastery estimates rather than free-form dialogue, especially in maths.
- **Open TutorAI CE** — the only one with voice + avatar out of the box.
- **GenMentor** — goal-first rather than curriculum-first: the learner names an outcome and the agents work backwards to a session plan. Choose it when the client's learners are adults with a job-shaped goal, not students following a syllabus.
- 🆕 **Profe Bit** — the first **programming** tutor on this shelf, and the only row that executes learner code **in the browser** (Pyodide), so there is no server-side sandbox to operate or secure. Socratic by construction: the course is negotiated in conversation, then delivered as challenges rather than lessons. Spanish-language, Universidad Nacional de Colombia. `0★`/151 commits/314 tests — prior art, not a dependency.

### Classroom simulation
- **OpenMAIC** — unique on this shelf: it simulates *peers*, not just a tutor. AI classmates that disagree create discussion dynamics a one-to-one tutor cannot.

### Teaching-workload automation
- **Instructional Agents** — full ADDIE cycle to slides and assessments. The natural fit where a client has a shortage of instructional designers rather than a shortage of teachers.
- **AI-Shifu** — the authoring end rather than the delivery end: capture a subject expert's intent once, generate an adaptive course from it, embed it in the client's own portal. Apache-2.0, so the generated product can be commercial.

### Mastery and retention
- **tutor-mcp** — the only row here that packages Bayesian Knowledge Tracing *and* FSRS spaced repetition behind a single MCP tool surface. It is the bridge between the mastery layer (`pykt-toolkit`, `fsrs-rs` in `repos/foundations.md`) and any agent above. See `compose/patterns.md` **P6**.

### Local-first and sovereign deployment
- **OpenTutor** — the row to reach for when the binding constraint is *where the data goes*, not what the tutor can do. Ollama by default, no API key, nothing leaving the machine, FSRS 4.5 in-tree for scheduling, and Canvas import when the client does have a cloud LMS. 166★.
- **OmniEdu** — the model-layer upgrade underneath it, once the weight licence is resolved.
- 🆕 **Profe Bit** — second entry in this category and the only one that is local-first at **both** ends: the model through an OpenAI-compatible local server (Ollama), and code execution through Pyodide in the learner's own browser. Nothing in the loop requires an egress path, which is the test that matters where student data cannot leave the building.

### LMS integration
- **canvas-mcp** — the bridge layer for Canvas, which dominates North American higher education. Any of the tutors above reaches real enrolment, assignment and grade data through an MCP server like this one. 317★.
- **moodle-mcp** — the same job for Moodle, which dominates LATAM and much of EMEA. 27★. The asymmetry between those two numbers is the single most actionable fact on this page; see the gap note below.
- 🆕 **TutorIA** — the **Open edX** entry this section was missing. It ships as an XBlock/plugin rather than a service, so the tutor lands *inside* the platform's own course, enrolment and grading objects instead of talking to them over REST. That makes it the cheapest of the three bridges to deploy and the most opinionated: it is an agent **and** its integration, where `canvas-mcp` and `moodle-mcp` are integrations awaiting an agent. 🔵 **So the LMS-bridge picture now reads Canvas 317★ → Moodle 27★ → Open edX (in-platform, 0★) → OpenOlat 0**, and only the Open edX slot is filled by something that already contains the pedagogy.

### Model layer
- **OmniEdu** — the only row here that is not an agent. When a client needs the *model* to know the curriculum rather than the *prompt* to carry it — sovereign deployment, offline deployment, or K-12 subject grounding that a general model guesses at — this is the base. The 9B FP8 checkpoint is ~11 GiB, which puts curriculum-grounded tutoring on a single GPU. Gate on the weight licence first.
